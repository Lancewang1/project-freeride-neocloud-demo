# 自动化与数据质量

## 使用

交付包根目录双击 `start-dashboard.cmd`：启动只监听127.0.0.1的本地看板，默认8765端口。按钮“采集并更新”执行真实采集、规范化、检验和看板生成，完成后重载；进程保持打开时每24小时更新一次。关闭进程即停止，不安装系统服务、不注册计划任务。端口冲突可用 `python scripts/serve_dashboard.py --port 8766`。命令行无浏览器模式用 `--no-browser`；禁止周期更新用 `--interval-hours 0`。

不运行服务也可直接打开 `dashboard.html`，包含全部数据，无CDN/网络依赖；它是离线快照，按钮会提示如何运行更新，不假装刷新。一次性更新运行包根目录 `powershell -ExecutionPolicy Bypass -File update.ps1`。换机器先 `python -m pip install -r requirements.txt`。当前机器依赖已就绪。

`collect_public.py`：公开GET，3并发、每个请求最长40秒读超时、最多3次重试；SEC顺序请求。失败记录URL/时间/错误；不绕过登录/验证码，不无限重试。JS动态页先寻找官方API、站点地图和附件；CoreWeave动态页面目前仅存档，财务改用SEC结构化数据。未配置Wind、富途未连接不妨碍这条公开源管线。

`build_data.py --as-of YYYY-MM-DD`：规范口径；默认本机日期。初次演示截止2026-10-21。API价格只能视为采集时快照，不能用这个参数制造过去价格。历史事实从官方带日期公告恢复，保存“期间、发布日期、抓取时间”三种时间。公告时分未核验，事件研究统一下一交易日收盘起算。跨期口径变化、语义不明的数据进复核队列。

`test_hypotheses.py`：输出逐事件与全期限/全基准统计。`build_dashboard.py`：嵌入数据生成离线HTML。所有脚本相对Skill根目录寻址，拷贝目录后可用。服务刷新错误保留旧HTML，在按钮状态和`data/update.log`显示失败；数据中间文件可能已更新，修复后应完整重跑四步，不能混用不同次运行的中间产物。

## 数据层和可审计性

- `data/raw/{sha256}.*`：原始字节快照，内容不变不重复存；PDF逐页文本另存。同一URL改版产生新哈希，旧快照保留。
- `data/runs/`：每次运行来源清单；`sources.json`是最近一次采集状态。
- `observations.json`：指标/实体/单位/口径/实际或指引/期间/发布日期/抓取时间/URL/哈希/原句/页码。
- `review-queue.json`：自动发现但不能可靠解释的文本。历史NBIS ARR采用已审阅哈希+页码+短锚；新季度不会靠宽泛关键词直接入库。需新增并验证选择器，保留人对财务语义的复核。这部分是辅助自动化，不是无人值守的财报理解。
- `sec-facts.json`：保留全部抓取到的财务标签期间与申报版本；看板选最新期间的最新申报值，**不是时点回测数据库**，不得用于未经vintage筛选的回测。
- `prices.json`：Yahoo调整后日收盘，剔除截止日当日；供应商调整和历史修订风险未消除。IPO/恢复交易之前不补价格。
- `event-study.json`：实际检验结果；将旧网页恢复的历史称为回溯重建，不能声称已具备真正point-in-time数据。以后新增快照才有前瞻归档证据。

在页面上同时查看披露日期与抓取日期：今天成功抓取不代表经营数据更新到今天。已采集的12类指标均为**部分覆盖**；例如现金不是完整资金缺口，电力指引不是已计费MW。数据量大也不提高缺失关键变量的可信度。

公开源足以做持续监测，但净价、利用率、客户信用和真实预期往往是机构研究的差异化数据，爬虫不是消除这些信息壁垒的万能工具。当前缺口明确呈现在看板，而不是人工填入估计值伪装自动化成果。
